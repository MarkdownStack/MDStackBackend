# MarkdownStack backend — context

FastAPI + MongoDB (via Motor, the async driver), JWT bearer auth, managed with `uv` (`pyproject.toml` + `uv.lock` — not `pip`/`requirements.txt`). Structured **by domain module** under `app/modules/` (router/schemas/models/service/repository per module), with cross-cutting concerns split into `app/core/`, `app/db/`, and `app/shared/`. Deployed as a Docker image; see **Deployment** below.

This layout is the result of a full restructure (see `PLAN.md` at the repo root for the phase-by-phase history — it's kept as the working record of *why* each piece landed where it did, not just a stale plan). Every route, status code, and response body was verified byte-identical to the pre-restructure code at each phase; nothing here changed API behavior.

## File structure

- `app/main.py` — `create_app()` + `lifespan` (replaces the old `@app.on_event`): CORS (`expose_headers=["Content-Disposition"]` so the frontend can read a download's real filename cross-origin), middleware registration (order matters — CORS outermost, `RequestIdMiddleware`, then `RequestCounterMiddleware` innermost), `register_exception_handlers`, includes `api_router`, runs `ensure_indexes()` on startup and closes the Mongo client on shutdown. The module-level `app = create_app()` is what `Dockerfile`'s `uvicorn app.main:app` imports.
- `app/api.py` — one aggregate `APIRouter` that includes every module's router, in the same order the original `main.py` did (users, notes, folders, search, tags, upload, public, comments, export, admin). `main.py` only ever imports this one router.
- `app/core/` — cross-cutting infrastructure:
  - `config.py` — the **one** place env vars are read now: `Settings(BaseSettings)` (pydantic-settings), `get_settings()` (lru\_cached). Every default matches the pre-restructure fallback exactly. Still calls `load_dotenv()` itself (belt-and-suspenders alongside pydantic-settings' own `.env` parsing) so `.env` is loaded before anything else in the app runs — same "read once at process start" gotcha as before: editing `.env` while `uvicorn` is running does nothing until restart.
  - `security.py` — bcrypt hashing, JWT encode/decode (`create_access_token`/`decode_access_token`).
  - `exceptions.py` — `AppError` domain hierarchy (`BadRequestError`/`ConflictError`/`NotFoundError`/`AuthenticationError`/`PermissionDeniedError`) + a handler that emits the exact same `{"detail": ...}` shape `HTTPException` always did. Every module's `service.py` raises these instead of importing `fastapi.HTTPException` directly.
  - `logging.py` — `configure_logging()`, new (there was no explicit logging config before).
  - `middleware.py` — `RequestCounterMiddleware` (see **Admin dashboard**) and `RequestIdMiddleware` (new — stamps `X-Request-ID` on every response, purely additive).
- `app/db/` — Mongo plumbing: `mongo.py` (the `AsyncIOMotorClient`/`db` handles, sourced from `Settings`, plus `close()` wired into the app's shutdown), `collections.py` (every collection reference as a plain module-level global — still created eagerly at import, same timing as before), `indexes.py` (`ensure_indexes()` — still the only place indexes are declared).
- `app/shared/` — cross-module pure helpers and the shared auth dependency: `markdown.py` (`extract_tags`/`extract_links`/`excerpt`), `paths.py` (`normalize_folder_path`/`folder_scope_pattern`), `datetime.py` (`now_iso`), `objectid.py` (`parse_object_id(id_str, on_invalid)` — one implementation shared by every place that converts a caller-supplied id to a bson `ObjectId`, each call site still passing in its own distinct failure — e.g. notes' own-vault routes 400 "Invalid note id", `public`/`comments` 404 so an unpublished note can't be told apart from a malformed id), `dependencies.py` (`get_current_user`/`get_current_user_optional`/`get_current_admin`/`is_admin_email`).
- `app/modules/` — one package per domain, each holding `router.py` (HTTP binding only), `schemas.py` (Pydantic request/response models), `models.py` (Mongo-document-to-schema mappers), `service.py` (business logic, raises `core.exceptions`), and `repository.py` (every Motor call for that module's collection):
  - `users/` — `/api/auth`: register/login/me, email verification, resend-verification, forgot/reset password. Also owns `email.py` (the Mailgun client — see **Accounts, auth, and email**) and, since author-name resolution is needed by nearly every other module, `derive_author_name`/`authors_by_owner_id` live in its `repository.py`.
  - `notes/` — `/api/notes`: private CRUD + `/published/mine`. Its `repository.py` also holds `text_search`/`tag_counts`/`list_by_tag`, reused by the thin `search`/`tags` modules below.
  - `folders/` — `/api/folders`: CRUD, and a **recursive cascade delete**: deleting a folder deletes it, every note inside it, every subfolder, and every note inside those subfolders (confirmed client-side first).
  - `public/` — `/api/public`'s note/folder reads + anonymous voting. `get_public_note_or_404`/`get_public_folder_or_404` in its `service.py` are the shared "is this actually published" gate — `comments` depends on the former (see below); `public` itself never depends on `comments`' service, only its `repository.py`'s pure `counts_for_notes`, so there's no import cycle despite the two-way conceptual relationship.
  - `comments/` — comment CRUD/upvote, still routed under `/api/public/notes/{note_id}/comments*` (own collection, own module, same prefix). Posting requires an account (resolved author, no anonymous spoofing); reading/upvoting stay open to everyone.
  - `search/`, `tags/` — **thin modules**: no collection or schemas of their own (neither ever had a `response_model`), just `router.py` + `service.py` calling into `notes/repository.py`.
  - `upload/` — bulk folder/file import (multipart, preserves relative paths via `webkitRelativePath`). Reuses `notes.repository.find_by_title`/`insert` and `folders.repository.find_by_path` directly; its own `repository.py` holds only the one query that couldn't be reused (`insert_bare_folder` — deliberately doesn't stamp `created_at`/`updated_at`, matching the original's exact document shape for upload-created folders).
  - `export/` — bundles selected folders (or the whole vault) into a streamed `.zip`. Uses `shared.paths.folder_scope_pattern` for its folder-scoping regex (this used to be an independently-duplicated copy of the same pattern — fixed as part of this module's migration, verified not to change behavior).
  - `admin/` — `GET /api/admin/stats`, gated by `get_current_admin`. See **Admin dashboard** below.
- `mcp_server/` — a separate MCP server; see its own section below. Untouched by the restructure — it's a plain HTTP client of this API and imports nothing from `app/`.

## Data model (Mongo collections, `app/db/`)

- **`users`** — `email` (unique index), `username` (sparse-unique — old accounts predating the username field have none), `password_hash`, `is_verified`, `verification_token`/`verification_token_expires` (sparse-unique, `$unset` once verified), `password_reset_token`/`password_reset_token_expires` (sparse-unique, same pattern), `created_at`/`updated_at`. No `is_admin` field — admin status is computed at read time from `Settings.admin_email_set`, not stored (see below).
- **`notes`** — scoped by `owner_id`; `title` unique per owner, full-text index on `title`+`content`, indexes on `folder_path`/`tags`/`links`/`is_public`+`upvotes`. `upvotes`/`downvotes` are anonymous and client-tracked via localStorage — no server-side vote-ownership (a documented "temperature, not a tamper-proof number" tradeoff). `created_at`/`updated_at` both round-trip to the frontend and are shown together in the note editor's title block. **Note**: a note created via `/api/upload` never gets `is_public`/`upvotes`/`downvotes` fields written at all (unlike `/api/notes` POST, which always sets them) — a pre-existing quirk, preserved deliberately; every read path defaults them via `.get(..., default)` so it's invisible at the API level.
- **`folders`** — scoped by `owner_id`; unique on `(owner_id, path)`, indexed on `(owner_id, is_public)` for the published-folders feed. **Note**: a folder created implicitly by `ensure_folder_chain` (upload's auto-created ancestor folders) has *only* `owner_id`/`path` — no `created_at`/`updated_at` — unlike one created via `POST /api/folders` or the publish-upsert, which always stamp both. Also preserved deliberately.
- **`comments`** — `note_id`+`created_at` and `note_id`+`upvotes` indexes (chronological list, and a future "top comments" sort). Author is always resolved from the real account — no free-typed names, no anonymous spoofing.
- **`request_stats`** — one doc per UTC calendar day, `_id` is the `"YYYY-MM-DD"` string itself (no separate index needed). Written only by `RequestCounterMiddleware`, read only by `GET /api/admin/stats`. See **Admin dashboard**.

## Accounts, auth, and email

Registration takes `username` + `email` + `password` (`USERNAME_PATTERN = r"^[a-zA-Z0-9_]{3,24}$"`, in `modules/users/schemas.py`, both stored lowercased for case-insensitive uniqueness). **Login accepts either** — `find_by_identifier(identifier)` in `modules/users/repository.py` queries `{"$or": [{"email": identifier}, {"username": identifier}]}`, and every recovery flow (resend-verification, forgot-password) takes the same `identifier` field for the same reason.

**Email verification is mandatory**: `POST /api/auth/login` returns 403 ("Please verify your email before logging in.") until `is_verified` is true. Registering sends a verification email (best-effort — a Mailgun failure doesn't fail the registration itself); `GET /api/auth/verify-email?token=` flips the flag. Tokens are `secrets.token_urlsafe(32)`, 24h TTL (`VERIFICATION_TOKEN_TTL` in `modules/users/service.py`). `POST /api/auth/resend-verification` and `POST /api/auth/forgot-password` both **always return the same generic `{message}`** regardless of whether the account exists or is already verified — a deliberate enumeration-prevention pattern, don't "fix" it to be more specific.

**Forgot/reset password** mirrors verification: `POST /api/auth/forgot-password` (generic response, 1h TTL — deliberately shorter than verification's 24h, since a reset link grants "set this account's password" outright with no old password needed) → emailed link → `POST /api/auth/reset-password` (token + new password) → `password_hash` updated, token fields `$unset`.

**`app/modules/users/email.py`** (moved from the old top-level `app/email.py`) is a thin Mailgun HTTP client (`httpx.AsyncClient`, `auth=("api", settings.mailgun_api_key)`), reading `Settings.mailgun_uri` (the full `.../messages` endpoint), `mailgun_api_key`, `mailgun_from_addr`, and `frontend_base_url` (used to build the `/verify-email?token=`/`/reset-password?token=` links — **must** be set to the real frontend origin before a real deploy, or emailed links point at `localhost:5173`). Both `send_verification_email`/`send_password_reset_email` are best-effort: they return `True`/`False` and never raise, so a Mailgun outage degrades to "no email sent" rather than breaking registration/reset requests outright. **Gotcha, still true after the restructure**: `Settings` is read once per process (`get_settings()` is `lru_cache`d) via `core/config.py`, so editing `.env` while a `uvicorn` process is already running does nothing until it's restarted — also check the process's cwd, since `load_dotenv()` resolves relative to it.

## Admin dashboard

Gated by `Settings.admin_emails` (comma-separated env var, e.g. `ADMIN_EMAILS=you@example.com,other@x.com`) — a config change, not a database write. `is_admin_email(email)` in `shared/dependencies.py` is the single source of truth (checking membership in `Settings.admin_email_set`), used both by `get_current_admin` (the dependency actually gating `/api/admin/*`, which does one extra DB round trip to fetch the caller's email — acceptable since admin endpoints are low-traffic) and by `modules/users/models.py`'s `to_user_out` (which surfaces it as `UserOut.is_admin`, purely so the frontend can show/hide admin UI without guessing — the endpoint itself still re-checks server-side regardless of what the frontend sends).

`RequestCounterMiddleware` (`app/core/middleware.py`) increments a per-UTC-day counter in `request_stats` on every real request, via `asyncio.create_task` (**not** awaited — never adds latency to the request it's counting) with the Mongo write wrapped in a bare `try/except` (a stats-recording failure must never break a real request). Skips `OPTIONS` preflights, `/api/health`, and `/api/admin/*` itself (so checking the dashboard doesn't inflate the number you're looking at).

`GET /api/admin/stats` (`modules/admin/`) returns: `total_requests` (sums every daily doc — cheap enough at this scale that a separate running counter isn't worth the extra write contention), `requests_today`, `requests_last_7_days` (a small per-day list), plus `total_users`/`total_notes`/`total_published_notes` since they were cheap to add alongside.

## Publishing, comments, and upvotes

A note's `is_public` toggle (and the equivalent for whole folders) makes it reachable without login. Comment posting requires an account (resolved author — no anonymous spoofing); reading and voting stay open to everyone. Three related-but-different feeds all exist: the anonymous public feed (`modules/public`), the logged-in "Explore" feed (excludes your own notes, via `get_current_user_optional`), and "My Published Notes" (`modules/notes`, only your own). All three resolve author names/comment counts through the same `modules/users/repository.py`'s `authors_by_owner_id` and `modules/comments/repository.py`'s `counts_for_notes` so they never drift out of sync with each other.

## Export

`modules/export/` bundles a hand-picked subset of folders (or the whole vault) into a streamed `.zip`, driven by the frontend's hierarchical folder-selection tree.

## MCP server (`backend/mcp_server/`)

A separate concern from the FastAPI app above: exposes the backend as ~22 tools for an MCP client (Claude Desktop, Claude Code, Claude.ai), covering auth, notes CRUD + publishing, folders (incl. cascading delete), search/tags, the public Explore feed + voting + comments, and vault export. Built as a plain `httpx` client of the *running* FastAPI backend (`mcp_server/client.py`), not a second copy of the business logic talking to MongoDB directly — every write still goes through the modules' own validation. Not covered: `/api/upload` (its multipart/`webkitRelativePath` shape doesn't map cleanly onto a tool call). Untouched by the backend restructure — it imports the API only over HTTP, never `app/` directly, so nothing about the module split affects it.

- Built on the standalone `fastmcp` package (pinned `fastmcp>=3.0,<4` — a prior `>=2.0,<3` pin silently resolved to an old `2.2.0` that lacked the `host`/`port` calling style `server.py` uses; see `mcp_server/README.md`'s "Which FastMCP?" section for the full `uv.lock` re-resolution story). `server.py` has a try/except import so it works both as a package (`python -m mcp_server.server`) and as a standalone script (`fastmcp run`/`dev`/`install`).
- **Two transports**: `MDSTACK_MCP_TRANSPORT` unset runs stdio (a local subprocess Claude Desktop spawns directly — local dev/testing). Set to `http` and it runs as a persistent Streamable HTTP service instead — what makes remote hosting possible.
- **Remote deployment**: an `mcp` service in `backend/docker-compose.yml`, on the same `app-network` as `backend`/`nginx`, talking to `backend` over Docker's internal DNS (not `localhost`). Built locally on the EC2 box via `build:` (unlike `backend`, which pulls a published image) — there's no CI job publishing an `mdstack_mcp` image yet. Exposed through nginx at `/mcp` on the existing domain/cert, with the three proxy settings Streamable HTTP needs that plain REST doesn't: `proxy_buffering off`, empty `Connection` header, long read/send timeouts.
- **Auth**: a single shared bearer token (`MDSTACK_MCP_TOKEN`, checked via `fastmcp.server.auth.providers.jwt.StaticTokenVerifier`) gates the whole `/mcp` path — a single-shared-secret model appropriate for "exactly one trusted caller," not multi-tenant OAuth.
- **Status, still unresolved**: `fastmcp` resolves to `3.4.0`, EC2 is redeployed on it, `curl https://api.stalk-my-money.in/mcp` correctly returns a JSON-RPC error (proof nginx → container routing works). Adding it as a remote connector in Claude Desktop still fails with "Couldn't reach MarkdownStack" even with a manual `Authorization: Bearer <token>` header — next step is comparing a real `POST .../mcp` against MCP's actual initialize handshake (`Accept: application/json, text/event-stream`) against `docker compose logs mcp`/`nginx` at the moment Claude attempts to connect, not just a bare `curl -i GET`.

## Deployment

- **CI/CD**: `.github/workflows/deploy_ec2.yaml` — on push to any branch, builds and pushes a Docker image (`parimalmahindrakar/mdstack_backend:<branch>_<short-sha>`) to Docker Hub; on `master` specifically, also tags/pushes `:latest` and SSHes into the EC2 box to redeploy via `docker-compose.yml` (backend + nginx + mcp services).
- **Dockerfile**: multi-stage — a `uv`-based builder stage with a compiler for native deps (bcrypt, pydantic-core), a clean non-root runtime stage with just the finished venv. `COPY app ./app` and the CMD's `uvicorn app.main:app` both still work unchanged post-restructure — everything stayed under `app/`, nothing moved to a new top-level directory. Verified with a real `docker build` + a container run against a throwaway Mongo on a docker network after the restructure landed.
- Tests are stubbed out in the CI workflow (commented-out MongoDB service + `uv run pytest` steps) — there's still no test suite (the restructure's own verification was a thorough *manual* pass per module against a throwaway local MongoDB, not an automated suite — writing one is a natural next step, tracked in `PLAN.md`'s Phase 0 as intentionally deferred this round).

`MONGO_URL`, `DB_NAME`, `CORS_ORIGINS` (**dead config** — `main.py` hardcodes `origins = ["*"]` and never reads this var; either wire it up or drop it from `.env.example`, don't assume it does anything today), `JWT_SECRET_KEY`, `JWT_ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`, `MAILGUN_URI`/`MAILGUN_API_KEY`/`MAILGUN_FROM_ADDR`/`FRONTEND_BASE_URL` (see **Accounts, auth, and email**), `ADMIN_EMAILS` (see **Admin dashboard**), `MDSTACK_MCP_TOKEN` (see **MCP server**). All read through `app/core/config.py`'s `Settings` now (`extra="ignore"` so the mcp-only `MDSTACK_*` keys don't hard-fail it) — see **File structure** above.

## Known open issues

- **Security, high priority**: see the repo root `SKILL.md` — the live Mongo Atlas password committed in `.env.example`. Don't remove the warning; owner rotates it on a call.
- **`CORS_ORIGINS` is unused** — see **Env vars** above.
- **MCP server**: no CI job builds/pushes an `mdstack_mcp` image yet (rebuilt from source on the EC2 box itself every deploy); the `mcp` container also currently pulls in the full base app dependency list (fastapi, motor, etc.) it never uses, since `pyproject.toml` doesn't separate "core app" deps from the `mcp` extra's own — harmless at this scale, would need its own `pyproject.toml`/lock to actually fix. The Claude Desktop remote-connector handshake failure above is still open.
- **Request-counter middleware**: `asyncio.create_task` fire-and-forget write has no backpressure — under a genuine traffic spike this could queue up a large number of pending Mongo writes; fine at this project's real-world scale, worth revisiting if traffic ever grows meaningfully.
- **No automated test suite** — see **Deployment** above. The restructure's PLAN.md lays out a Phase 0 test-writing plan (a frozen route list + OpenAPI baseline, per-module smoke tests against a throwaway MongoDB) that was deliberately deferred rather than done as part of the restructure itself.
- **Deferred, tracked in `PLAN.md`, not done this round**: pagination on `/api/notes`/`/api/folders` (currently unbounded); the N+1 `count_documents` loop in `list_public_folders`/`list_my_published_folders` (one query per folder in the list, could be a single `$group` aggregation like `comments.repository.counts_for_notes`); wiring `CORS_ORIGINS` for real.
